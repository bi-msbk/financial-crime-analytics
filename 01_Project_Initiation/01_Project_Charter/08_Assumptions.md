# Project Assumptions

The project is based on the following assumptions. These assumptions may be reviewed and updated as the project progresses.

| ID | Assumption | Category |
|---|---|---|
| A-001 | All project data will be synthetic. | Data |
| A-002 | The dataset will represent a realistic but fictional UK retail banking environment. | Business |
| A-003 | Historical fraud outcomes will be available for analytical purposes. | Data |
| A-004 | Historical transaction behaviour can be used to establish customer behavioural baselines. | Analytical |
| A-005 | Existing fraud-monitoring rules can be represented using simplified analytical logic. | Analytical |
| A-006 | The project does not represent actual Barclays, JPMorgan Chase, Lloyds Banking Group or any other bank's internal processes, systems or data. | Portfolio |
| A-007 | No personally identifiable information will be generated or used. | Privacy |
| A-008 | Historical transaction timestamps, amounts, channels and behavioural attributes will be available for analysis. | Data |
| A-009 |  Merchant, device and geographic attributes will be included in the synthetic dataset where required to support the approved analytical objectives.
| A-010 | Fraud-monitoring controls will be simplified for the purposes of this portfolio project. | Analytical |
| A-011 | The project will use historical labelled data for fraud analysis and model development. | Modelling |
| A-012 | Historical fraud labels are sufficiently reliable for analytical use after data-quality validation. | Modelling |

## Assumption Review

Assumptions will be reviewed when new data requirements, analytical limitations or project dependencies are identified.

Where an assumption becomes invalid, the impact on scope, analytical methodology and project outcomes will be assessed and documented.
